## 已确认的当前规则

1. 当前题目仍为 v1、CANN 9.1.0、judge_revision=0、score_mode=1、iterations=5、use_baseline=false、ranking_submission_mode=latest，ranking_testcase_count=null。题面仍要求与原 TBE PadV3Grad 核心功能一致、支持合法输入泛化、所有用例通过；默认精度阈值 float=1e-4、half=1e-3、int=0。这些阈值不能单独还原完整误差比较算法。
2. 官方平台公开的[默认评分规则生成器](https://cannjudge.cn/js/pages/scoring-rules-content.js)规定普通算子每测试点分数为 `100 / (1 + log(time / TBest) / log(1.5))`，单题取全部测试点得分平均并保留两位小数。TBest 是该测试点所有参赛者提交的历史最快用时，会被后续更快提交刷新。当前官方前端表单将 score_mode=1 标为“按全部测试点”；rank count 留空表示全部计入。该来源是平台公开默认规则文案与其声明，不是独立取得的后端实现；不要把隐藏用例值代入推算总分，正式指标仍取精确任务绑定的 `row.score`。
3. [当前赛事规则页](https://cannjudge.cn/public/ictcompetition/scoring-rules)的自定义正文实际链接到华为[评分机制文章](https://e.huawei.com/cn/talent/news/#/details?consultationId=5762)。该文章（页面显示发布于 2026-06-16）说明单题基础分满 100、按队伍最新提交排名、难/中/易分别乘 3/2/1，单题第一另加 30/20/10，赛事总分相加。它没有说明底层耗时评分公式、计时方法或退化门槛。不得把平台通用模板里的难度系数 1~5 范围改写为该赛事专门规则。
4. 当前前端将可见 `time`/`best_time` 数值作为微秒显示，达到 1000 时转为毫秒。这只能证明显示单位。`iterations=5` 在表单标为循环次数，不能据此设定预热、内层重复数或中位数规则。
5. 前端排行榜请求使用 `page`、`size`，size 最大 100，可选 `q`。此前使用 page/size 并非参数名错误。latest 模式会被后续提交覆盖；没有某个旧任务行不能解释成 0 分，具体缺行原因仍须对应观察证据。
