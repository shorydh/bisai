# 算子优化协作仓库

用于 Agent A、B、C 的实验交接，以及中央 Agent 的复盘、任务派发和基线审核。

## 队友接入

1. 使用自己的 GitHub 账号登录。
2. 在本仓库 Issues 中选择“团队加入申请”，填写执行者代号并提交。
3. 将申请链接交给仓库所有者。申请本身不会自动授予写入权限；所有者发送协作者邀请后，申请者需要接受邀请。
4. 获得权限后，使用自己的工作分支交接材料，不直接合并其他执行者的代码。

## 分支约定

- `main`：共同说明、中央审核后的共享资料与基线记录。
- `agent-a`、`agent-b`、`agent-c`：三名执行者分别使用的工作分支。
- 中央 Agent 审核时读取各工作分支的明确提交编号，不只读取 main。

## 资料位置

```text
members/                                  # 成员及接入说明
operators/Q01/round-001/A/summary.md       # 实验总结
operators/Q01/round-001/A/experiments.jsonl # 实验记录
operators/Q01/round-001/A/artifacts/       # 对应代码与评测证据
central/Q01/round-001/                     # 中央复盘、任务单与基线记录
```

题目、轮次和执行者按实际情况替换。每份结果都应能追溯到实际评测的代码版本。

## 实验与交接

- 每个完成修改且具备评测条件的实验版本都进入官方提交环境测试，获得结果后再汇总。
- 云环境用于编译、调试和分析；正式性能比较与共同基线更新采用同一官方评测口径下的有效结果。
- 保留失败和退化记录；官方未提供的指标不补造。
- 中央 Agent 先汇总发现，再决定复测或组合实验。组合方案重新验证，通过验收后才更新共同基线。
- 本仓库初始化不代表任何算子已完成验证，也不代表任何成员已经获得写入权限。

## 仓库公开后的资料范围

只提交可公开的协作材料。不提交登录凭据、访问令牌或不允许公开的赛题、测试数据与其他文件。
